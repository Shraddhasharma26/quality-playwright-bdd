what is this cherry picking ? why it is required ?

What it is: git cherry-pick takes one or more existing commits from some branch and reapplies their changes as new commits onto your current branch.
Why use it: to move only specific changes (bugfixes, features) onto another branch without merging the entire branch history. Useful when you want some local commits on top of origin/main but must exclude a bad commit (e.g., one containing a secret).

Risks & notes:

You can get merge conflicts (you saw these) which must be resolved with git add + git cherry-pick --continue (or abort).
Cherry-picks create new commits (different hashes) — history is not identical to merging.
If a commit contains secrets, cherry-picking it (or merging it) will still include the secret in history and can trigger GitHub push-protection (as happened with the flagged commit).
Alternatives:

git merge or git rebase (bring the whole branch instead of selective commits).
Create a patch: git format-patch + git am.
If a secret is already committed, remove it from history using git filter-repo / BFG and then force-push (careful, disruptive).
